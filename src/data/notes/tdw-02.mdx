## **1) Local environment setup**

### **1.1) Installing an IDE**

- [Visual Studio Code](https://code.visualstudio.com/)
- [PhpStorm / WebStorm](https://www.jetbrains.com/phpstorm/) — you can create a student account with your UA email address through [JetBrains for Education](https://www.jetbrains.com/community/education/#students).

### **1.2) Install Git**

[git-scm.com](https://git-scm.com/), preferably v2.55.0 or newer.

- [Windows](https://git-scm.com/download/win)
- [Mac OSX](https://git-scm.com/download/mac)
- [Linux](https://git-scm.com/download/linux)

### **1.3) Install Node & NPM**

[nodejs.org](https://nodejs.org/) — install the current LTS, v24.21.0.

- [Via package manager](https://nodejs.org/en/download/package-manager)
- Windows — [x64](https://nodejs.org/dist/v24.21.0/node-v24.21.0-x64.msi) or [arm64](https://nodejs.org/dist/v24.21.0/node-v24.21.0-arm64.msi)
- [Mac OSX](https://nodejs.org/dist/v24.21.0/node-v24.21.0.pkg)
- [Linux](https://nodejs.org/dist/v24.21.0/node-v24.21.0-linux-x64.tar.xz)

Once installed, check both are available:

```bash
node -v
npm -v
```

<Aside>

Juggling projects that need different Node versions? Install it through a version manager such as [nvm](https://github.com/nvm-sh/nvm) (or [nvm-windows](https://github.com/coreybutler/nvm-windows)) and switch with `nvm use 24`.

</Aside>

## **2) Create a repository on GitHub**

1. If you don't already have one, create a [GitHub account](https://github.com).
2. Create a repository in the organisation with a name for the TDW practical classes project.
3. Create a folder on your computer where you keep your class projects.
4. Clone the repository into that folder — the clone creates a subfolder named after the repository, so you don't need to create it yourself.

<Aside>

Bonus tip: with your UA email you can access [GitHub Education](https://github.com/education), which gives you GitHub Pro, Copilot, and more.

## **3) Initial project setup**

Open a command line and navigate to the location where you created the folder for the class. To move around the file system in the terminal you can use:

- `pwd` — show the path to the folder where you are
- `ls` — list files and folders
- `cd abc` — navigate to a folder called "abc"
- `cd ..` — navigate out of a folder

Some useful links:

- [Command line for beginners](https://ubuntu.com/tutorials/command-line-for-beginners)
- [Learn the command line](https://www.codecademy.com/learn/learn-the-command-line)
- [linuxcommand.org](http://linuxcommand.org/)

Create a new Next.js project with the following command (you may need to install the package):

```bash
npx create-next-app@latest
```

When asked for the project name, write `tdw-your-name`. For now let's keep it simple and answer **No** to any additional extensions (e.g. ESLint or Tailwind) — Part 6 starts from a project without a linter.

<Aside>

Running this inside your cloned repository will create a nested folder. If you'd rather have the app at the root of the repository, run `npx create-next-app@latest .` from inside it.

</Aside>

Navigate to the folder and check its contents:

```bash
ls -la
```

Then run:

```bash
npm run dev
```

In a browser, navigate to [http://localhost:3000/](http://localhost:3000/). Congratulations, you have completed the initial setup! Open the project folder in your IDE and explore its contents.

## **5) Create a new page**

First, check if the local repository is up to date:

```bash
git pull
```

Create a local git feature branch to develop a new page for the application. You can check the existing branches with `git branch` — see the [feature branch workflow](https://www.atlassian.com/git/tutorials/comparing-workflows/feature-branch-workflow).

1. In the new branch, create a new page for your application and add some content to it. The content itself is not particularly important; it could be anything: a paragraph of text, an image, etc.
2. Check for the existence of two branches.
3. Switch to the selected branch.
4. Create a commit on the same branch with your changes, including a message describing what you did.
5. [Push your branch](https://www.atlassian.com/git/tutorials/syncing/git-push) to the remote repository — the new one will need to be created in the remote repository.
6. From that branch, open a pull request with your changes — GitHub's name for what GitLab calls a merge request.
7. Merge these changes.
8. Delete the temporary branch, if it is a feature you will no longer be working on.

Some useful links:
